# 2026-10-26 政策修订摘要

本摘要说明公开副本保留的政策改动。版本定位使用仓库的 Git tag `v1.0.0`，后续修改以发布标签及仓库差异为准。

| 范围 | 改动 |
| --- | --- |
| 任务可派发性 | 执行前检查输入与约束，减少无历史交接遗漏。 |
| 派发记录 | 记录首发结果、耗时、返修和深入核验；缺失数据明确标记。 |
| 调度开销 | 同一上下文与验收目标的小改动优先合并，避免无收益的交接。 |
| 长任务 | 设定检查点、停止条件并汇总父任务预算；区分检查点与硬上限。 |
| 失败分类 | 先核对任务卡是否传入约束；交接遗漏单列，不自动归因于能力。 |
| 返修上限 | 已实施后的交接返工仅在非 U 且有额度时允许，消耗一次同档修复及五轮额度。 |
| 升级交接 | 列明已接受成果与允许修改部分；新依赖缺陷须有证据才能重开。 |
| 独立对话 | 区分内部子代理与用户要求的新聊天；按工具 schema 和授权设置模型及工作环境。 |
| 效果校准 | 以同类任务和可取得的计量比较；不默认双跑、不凭缺失计量宣称省钱。 |

这些是提示词政策改动，不证明实际节省成本或提高首发通过率。公开打包适配删除了私人路径和操作历史，将工具与模型说明标为环境示例，并移除了未经本次核验的价格及官方模型定位断言。

格式检查只能验证 skill 结构，不能证明调度行为、模型可用性或真实成本效果；公开副本尚无新的运行效果验证。
